🧭 Module roadmap

  • 1. Airflow Concepts: DAGs, Tasks and SchedulingAirflow orchestrates work; it is not the data warehouse.
  • 2. Operators, Sensors, XCom and VariablesOperators do work; sensors wait; XCom passes small metadata; Variables hold configuration.
  • 3. Dependencies, Retries, Backfills and SLAsRetry transient failures; backfill deliberately; avoid duplicate side effects.
  • 4. Composer Architecture and Production PracticesManaged Airflow still needs clean DAGs, secrets, dependencies and monitoring.
  • 5. ELT with dbt: Models, Tests and Documentationdbt turns SQL transformations into versioned, tested, documented models.
  • 6. Incremental dbt Models and SnapshotsIncremental models reduce repeated work; snapshots preserve historical state.
  • 7. Orchestrating Spark, Dataflow and BigQueryUse orchestration for dependency control, not business logic duplication.
  • 8. End-to-End Airflow + dbt PipelineIngest → stage → transform → test → publish → observe.

🏭 Industry scenario

A production data team is building a platform where the same concepts must work across development, testing and production. The design is judged by correctness, scale, security, cost and operability, not only by whether code runs once.
