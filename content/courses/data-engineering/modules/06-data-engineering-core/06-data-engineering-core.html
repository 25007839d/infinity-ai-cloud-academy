🧭 Module roadmap

  • 1. Data Modeling FundamentalsModel the business grain before choosing the physical table.
  • 2. Dimensional Modeling: Facts and DimensionsFacts answer how much/how many; dimensions answer by whom/what/where/when.
  • 3. Star and Snowflake SchemasStar optimizes usability; snowflake normalizes dimensions.
  • 4. Data Ingestion PatternsChoose batch, micro-batch or streaming from freshness and operational needs.
  • 5. Incremental Loads and CDC ConceptsMove only what changed; keep a reliable change key.
  • 6. Partitioning, Clustering and File LayoutPartition prunes large ranges; clustering improves locality inside them.
  • 7. Data Contracts and Schema EvolutionA contract makes producer and consumer expectations explicit.
  • 8. Lakehouse Table Formats and MetadataTable formats add schema, snapshots and transactional semantics to object storage.

FROM fact_sales

🏭 Industry scenario

A production data team is building a platform where the same concepts must work across development, testing and production. The design is judged by correctness, scale, security, cost and operability, not only by whether code runs once.

🧪 Module practice

  1. Pick one topic and explain it using the visual.
  2. Recreate the code pattern without copy-paste.
  3. Change one requirement and explain what must change.
  4. Add one quality check.
  5. Describe one failure and recovery path.

📝 Assessment

Complete the module practice, lab and assignment with implementation, sample input/output, validation evidence, one failure-handling decision and a short README.
